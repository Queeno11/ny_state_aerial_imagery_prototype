# Continue ordinal training and fit matched likelihood

Run from `src` in WSL Bash with `torch_geo_env` activated. The existing `ordinal_latent_core` directory and both original Python drivers are read-only inputs. **Implementation was not trained or tested on this machine.**

```bash
conda activate torch_geo_env
python ordinal_mc_suite/ordinal_latent_extension.py --plan
python ordinal_mc_suite/ordinal_latent_extension.py --self-check
set -o pipefail
python ordinal_mc_suite/ordinal_latent_extension.py --smoke --baseline ordinal_mc_suite/ordinal_latent_smoke --output ordinal_mc_suite/ordinal_latent_extension_smoke --device cuda 2>&1 | tee ordinal_latent_extension_smoke.log
python ordinal_mc_suite/ordinal_latent_extension.py --mode continue --device cuda --output ordinal_mc_suite/ordinal_latent_extension_results 2>&1 | tee ordinal_latent_extension_training.log
python ordinal_mc_suite/ordinal_latent_extension.py --mode benchmark --device cuda --output ordinal_mc_suite/ordinal_latent_extension_results 2>&1 | tee ordinal_latent_extension_ml.log
```

The smoke selects the **existing smoke baseline explicitly**, restores its step 2 checkpoint and advances to steps 3/4 in an independent directory. Its 12 likelihood fits use at most 20 LBFGS iterations per fixed start and are small implementation probes; expect uncertified optimization status. They cannot be combined with full-run estimates. Full defaults restore the 12 `nn`, `ranknet`, cross-on trajectories at 4,800 total updates and continue to 9,600 and 19,200, or 4,800 and 14,400 **additional** updates. With 16 cities and 12 paired tracts per update out of 64 × 250, these endpoints represent 115.2 and 230.4 selected-tract passes (not sequential epochs). There is no target-truth selection, stopping, or further automatic extension.

`--mode all` performs both phases, while `--mode continue` and `--mode benchmark` can run sequentially in either order in the **same extension output**. The benchmark is 3 seeds × 4 latent scenarios × 3 outcome maps = **36 full-panel fits**. A given likelihood fit is reused across cross-link arms because its source fitting panel does not change. `--methods nn basis supervised` and `--cross 0 1` enable other existing trajectories explicitly; supervised uses its baseline cross-off run once. `--targets 9600 19200` specifies absolute optimizer steps. `--ml-iterations 1000` is the per-start LBFGS iteration cap and `--ml-starts 2` uses two fixed generic starts. The likelihood and continuation both use `--device cuda` by default; CPU is available explicitly, but changing device can change numerical replay of CUDA checkpoint updates. Changed statistical options or code require a new extension output directory. `--plan` checks baseline hashes and expected checkpoint files and writes nothing; `--self-check` runs only structural checks and an optimizer-moment checkpoint roundtrip in a temporary directory.

The extension rejects changed hashes of the frozen diagnostic or pilot, missing baseline checkpoints, and a changed extension manifest. Each trajectory records the SHA256 of the exact baseline checkpoint and fingerprints generated panels. It reconstructs feature standardization, fixed temporal and cross links, batches, Adam hyperparameters, and optimizer/RNG states from the baseline, saving separate atomic checkpoint, sampled-objective, and metric files. Repeating a command resumes the last new checkpoint; interrupted diagnostics are recreated from the saved state. Only load trusted local `.pt` checkpoints.

The parametric benchmark observes the **same 64 × 250 paired source fitting panels** and their W values. It knows the correct linear or full quadratic H basis, Gaussian sigma and within-tract rho, correct M1/M2/M3 Psi family, and population reference mean/covariance normalization. It estimates every identifiable basis coefficient ratio and separate city/date map intercept, slope (fixed at one for M1), and tanh shape (M3) using the full paired Gaussian likelihood with inverse map and Jacobian. Fixing the first basis coefficient to positive one removes an unidentifiable radial degree of freedom; this happens to match these scenarios' orientation and is a disclosed favorable structural assumption. M2/M3 slope uses a positive transform plus a `0.0001` floor; M3 tanh shape is constrained to the open interval `(0, 2)`, which contains the true shapes. Initialization uses two generic H0-dominant directions (remaining coefficient ratios zero or 0.12); true coefficients, true cell map parameters, and fitting latent f labels do not initialize, optimize, or select a likelihood fit. Cell parameters are freely fitted within each correct family; the generator's context formulas are not imposed. Sigma/rho and basis/reference family are known design privileges. The lowest finite **training** NLL selects between the two fixed starts, including if its gradient tolerance is not met. LBFGS gives a finite-budget local numerical result, not a proof of global optimum or efficiency. Each fit saves per-start loss, improvement, gradient norm, actual iterations, closure calls, cap, and convergence flag; a final gradient norm above `1e-4` is marked `not certified`. Reaching the iteration cap is also recorded independently. Passing this gradient check does not certify a global optimum.

The primary ML comparison uses **the same fitting-f-only positive affine alignment** as the ordinal NN and then applies the same true target city/date conditional mean oracle map to its inferred f. This removes outcome-head estimation error on both sides. A secondary `raw canonical` ML evaluation omits that alignment to expose sensitivity to normalization. The M3 conditional mean integrates `tanh(f + eta)` by the same Gaussian quadrature; it is not the structural `Psi(f)`. Both source and target results record f, conditional mu, delta f, and delta mu MSE, along with bias, slope, stable movement and detection on independent stable threshold panels, and all/stable/small/large strata. No target map or target latent truth is fitted. True maps and Gaussian marginal are evaluation-only oracle privileges; these curves do **not** predict a fully deployable model.

`combined_metrics.csv` labels frozen baseline rows separately from continued checkpoints and fitted likelihood. `ml_metrics.csv` and `ml_*.json` retain seed-level likelihood results and optimization status. The static `comparison_*.png` figures show target metric trajectories and the matching ML horizontal seed mean/range for each scenario/map; an orange benchmark line explicitly counts uncertified fits. Preserve seed pairing in downstream comparisons. Baseline NN cross-on/off, basis cross-off, and direct-f supervised curves stay labeled by method and end at their original 4,800-update budget. The fit JSON and continuation states remain separate from the baseline. See `REPORT.md` in the extension output for completion counts and per-fit uncertified statuses.
